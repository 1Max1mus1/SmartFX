# SmartFX 留学生缴费助手 PRD

## 1. 文档信息

| 项目 | 内容 |
| --- | --- |
| 功能名称 | 留学生缴费助手 |
| 所属产品 | SmartFX |
| 版本 | v0.1 Draft |
| 文档类型 | 增量 PRD |
| 目标入口 | `apps/web/app/assistant/page.tsx` |
| 目标用户 | 需要在缴费截止日前完成学费/押金/生活费相关换汇支付的留学生与家长 |
| 币种范围 | 仅限现有 `USD / HKD / CNY` |
| 产品定位 | AI 场景化换汇参考工具，不构成投资建议 |

> 合规说明：本功能输出的是“缴费时机建议”和“参考信号”，不是收益承诺、价格预测或投资建议。

---

## 2. 背景与目标

### 2.1 背景

当前 SmartFX 已有：

- AI 对话助手：适合自由问答
- 汇率统计能力：支持实时汇率、7/30/90 天分位、涨跌幅
- 结算分析能力：适合通用的结算时机建议

但对于留学生用户来说，现有产品还缺一个更贴近实际决策的场景入口：

- 用户不是想泛泛地问“美元高还是低”
- 用户真正想知道的是“我 X 月 X 日前要交学费，现在该不该交”
- 用户最担心的是“刚交完，汇率又跌很多，产生遗憾”

因此需要把通用 AI 能力产品化为一个结构化的“留学生缴费助手”。

### 2.2 产品目标

在 AI 助手页中新增一个结构化模块，让用户输入缴费期限和基础信息后，系统直接给出：

- 今天是否建议支付
- 当前汇率是否属于偏低区间
- 如果不今天交，建议观察多久
- 是否适合一次性交还是分批交
- 决策依据是什么

### 2.3 核心目标

1. 帮助用户把“汇率高低判断”转化为“缴费动作建议”。
2. 让建议具备可解释性，不只是 AI 一段话。
3. 尽量减少用户因截止日临近或汇率波动造成的后悔感。

### 2.4 非目标

本版本不做以下内容：

- 不新增 `GBP / AUD / CAD` 等币种
- 不做真实未来汇率预测模型
- 不做自动提醒、自动支付、自动下单
- 不做支付渠道接入
- 不做复杂用户画像学习

## 3. 目标用户与痛点

### 3.1 目标用户

- 中国内地留学生
- 香港留学用户
- 留学生家长
- 需要短期内完成一次或多次缴费的用户

### 3.2 典型场景

1. 用户需在 7 天内把人民币换成美元缴学费。
2. 用户需在 3 天内把人民币换成港币缴学费或押金。
3. 用户已经有部分美元/港币余额，想知道今天是否应该补足剩余款项。

### 3.3 核心痛点

- 不知道当前汇率到底算不算低
- 不知道该今天交、等几天、还是分批交
- 不知道“时间压力”应该比“汇率点位”更优先还是更次要
- 害怕刚支付完汇率又明显下跌

## 4. 产品定义

### 4.1 功能名称建议

对外展示文案建议使用：

- `留学生缴费助手`
- 副标题：`根据缴费截止日与当前汇率，给出可执行的缴费时机建议`

不建议直接用“预测”作为主标题，以降低承诺感和合规风险。

### 4.2 产品形态

在现有 AI 助手页中新增一个结构化卡片区，位于自由聊天区上方或左侧信息卡区域。页面保留原有自由聊天能力。

### 4.3 页面结构

建议由三部分组成：

1. 快捷入口区
   - `今天适合缴学费吗`
   - `当前汇率算低吗`
   - `我应该一次性交还是分批交`

2. 结构化表单区
   - 让用户填写缴费信息

3. 结果展示区
   - 用卡片而不是纯长文展示结论
   - 支持“继续追问”进入下方聊天区

## 5. 输入与输出

### 5.1 输入字段

| 字段 | 是否必填 | 类型 | 说明 |
| --- | --- | --- | --- |
| `deadline_date` | 是 | date | 缴费截止日期 |
| `amount` | 否 | number | 缴费金额；为空时只做时机判断，不做金额影响测算 |
| `source_currency` | 是 | enum | 默认 `CNY`，允许 `USD/HKD/CNY` |
| `target_currency` | 是 | enum | 允许 `USD/HKD/CNY` |
| `can_split_payment` | 是 | boolean | 是否接受分批支付 |
| `risk_preference` | 是 | enum | `stable` / `balanced` / `opportunistic` |
| `notes` | 否 | string | 给 AI 的补充描述，如“家里这周只能操作一次” |

### 5.2 推荐默认值

- `source_currency = CNY`
- `target_currency = USD`
- `can_split_payment = true`
- `risk_preference = balanced`

### 5.3 输出结构

结果必须结构化，至少包含以下字段：

| 字段 | 说明 |
| --- | --- |
| `decision` | 最终建议，例如“建议今天支付” |
| `decision_level` | `pay_now` / `split_now` / `watch_short` |
| `decision_reason` | 一句话解释核心原因 |
| `rate_assessment` | 当前汇率属于偏低/较低/中位/偏高 |
| `deadline_pressure` | 截止时间紧迫度：高/中/低 |
| `suggested_action` | 清晰动作建议 |
| `split_payment_plan` | 若支持分批，则给出建议比例和观察窗口 |
| `market_snapshot` | 当前汇率、24h 变化、30d 分位、90d 分位 |
| `analysis_markdown` | 给聊天区或展开查看的长文本说明 |
| `disclaimer` | 固定免责声明 |

## 6. 核心决策逻辑

### 6.1 设计原则

本功能采用“规则底座 + AI 解释增强”的模式：

- 规则层负责可控结论
- AI 层负责把理由转成用户能理解的话

不能把最终决策完全交给大模型自由发挥。

### 6.2 当前汇率算不算低

首版直接基于已有 `RateService.get_stats()` 能力做判断。

建议口径：

| 近 30 天分位 | 判断标签 | 对用户解释 |
| --- | --- | --- |
| `<= 20%` | 偏低 | 当前汇率位于近 30 天较低位置 |
| `20% - 40%` | 较低 | 当前汇率略偏低，可考虑执行或分批执行 |
| `40% - 70%` | 中位 | 当前汇率不算明显低位，更需要结合截止日 |
| `> 70%` | 偏高 | 当前汇率偏高，如时间允许可短观察 |

### 6.3 截止日压力判断

| 距截止天数 | 压力等级 | 策略倾向 |
| --- | --- | --- |
| `<= 2` 天 | 高 | 优先确保支付完成，不建议继续等待 |
| `3 - 7` 天 | 中 | 可考虑短观察或分批 |
| `> 7` 天 | 低 | 可以给更多观察空间 |

### 6.4 建议动作规则

首版建议三类动作：

1. `pay_now`
   - 截止时间很近
   - 或当前汇率已处于偏低区间

2. `split_now`
   - 用户可接受分批
   - 当前汇率处于较低或中位
   - 仍有少量观察空间

3. `watch_short`
   - 截止时间不紧
   - 当前汇率偏高或中位偏高
   - 允许短时间观察 1-3 天

### 6.5 风险偏好对建议的影响

| 风险偏好 | 倾向 |
| --- | --- |
| `stable` | 更倾向今天执行或先付大头 |
| `balanced` | 更倾向分批 |
| `opportunistic` | 在截止压力不高时允许更短期观察 |

### 6.6 分批建议

当 `can_split_payment = true` 时，系统可输出示例方案：

- `70% + 30%`
- `50% + 50%`
- `80% + 20%`

选择逻辑：

- 截止越近，首次支付比例越高
- 用户越求稳，首次支付比例越高
- 当前汇率越偏低，越倾向先锁定更多比例

## 7. 用户流程

### 7.1 主流程

1. 用户进入 AI 助手页
2. 看到“留学生缴费助手”卡片
3. 输入截止日期、币种和可选金额
4. 点击 `生成缴费建议`
5. 页面展示结构化结果
6. 用户点击 `继续追问`，把结果带入下方聊天上下文

### 7.2 结果页展示优先级

结果页必须先展示结论，再展示解释。

建议展示顺序：

1. 今日建议
2. 当前汇率位置
3. 截止日压力
4. 一次性支付建议
5. 分批支付建议
6. 风险提醒与免责声明

## 8. 前端需求

### 8.1 页面范围

目标页面：

- `apps/web/app/assistant/page.tsx`

### 8.2 新增模块

建议新增：

- `StudentPaymentAdvisorCard`
- `StudentPaymentAdvisorForm`
- `StudentPaymentAdviceResult`

### 8.3 交互要求

- 表单提交时显示 loading
- 响应失败时展示明确错误文案
- 支持快速填充示例问题
- 结果支持一键带入聊天区继续追问

### 8.4 文案要求

用词统一为：

- `建议`
- `参考`
- `偏低 / 较低 / 中位 / 偏高`
- `观察窗口`

避免使用：

- `预测一定会跌`
- `抄底`
- `稳赚`
- `最佳买点`

## 9. 后端需求

### 9.1 建议新增接口

`POST /api/ai/student-payment-advice`

说明：

- 专用于留学生缴费时机建议
- 不替代现有 `/api/ai/chat`
- 输出结构化结果

### 9.2 建议新增 schema

- `StudentPaymentAdviceRequest`
- `StudentPaymentAdvicePayload`

### 9.3 建议新增 service

- `StudentPaymentAdviceService`

职责：

- 校验输入
- 调用现有汇率统计能力
- 计算分位、紧迫度、动作建议
- 调用 AI 做自然语言补全
- 输出结构化结果

### 9.4 与现有能力的复用关系

可复用：

- `RateService.get_live_conversion_rate`
- `RateService.get_stats`
- `KimiClient`
- 现有 disclaimer 体系

可参考但不建议直接耦合：

- `SettlementService`

原因：

- 现有结算服务偏通用结算场景
- 留学生缴费有自己的字段和表达方式
- 新服务独立后更利于 UI 和文案控制

### 9.5 AI 输出策略

不建议让大模型直接决定最终动作。

建议策略：

1. 后端先算出：
   - 汇率位置
   - 截止压力
   - 动作建议
   - 分批建议

2. 再把这些结论交给 Kimi 生成：
   - 用户友好的说明
   - 风险提醒
   - 可继续追问的分析文本

## 12. 验收标准

### 12.1 产品验收

- 用户可在 AI 页面直接找到留学生缴费助手入口
- 用户输入截止日期后能获得结构化建议
- 结果中明确回答“今天是否建议支付”
- 结果中明确回答“当前汇率算不算低”
- 结果中包含可执行动作，而不是只有分析描述

### 12.2 技术验收

- 新接口响应结构稳定
- 错误状态下前端有清晰提示
- AI 不可用时仍有规则 fallback
- 输出统一包含免责声明

### 12.3 合规验收

- 页面与接口文案中不出现收益承诺
- 不出现“保证”“抄底”“稳赚”等表达
- 明确说明仅供参考

## 13. 风险与应对

| 风险 | 说明 | 应对 |
| --- | --- | --- |
| 用户把建议当成预测 | 误解产品能力边界 | 用“建议”“参考”替代“预测” |
| 大模型输出过度承诺 | 文案可能失控 | 规则先决策，AI 只解释 |
| 截止日输入错误 | 导致建议偏差 | 前端展示明显提示，说明结果依赖用户输入 |
| 币种能力不足 | 不能覆盖更多留学国家 | 本版明确只支持 `USD/HKD/CNY` |

## 15. 结论

这不是一个新的独立产品页，而是对现有 AI 助手页的场景化增强。核心价值不在“分析更多”，而在“把留学生真正关心的问题，用结构化、可执行、可解释的方式回答出来”。

如果后续进入开发，建议先按本增量 PRD 独立实现，再视效果把相关内容并入主 PRD。
